# ADR-0056: CI Process Checks

**Status:** Proposed
**Date:** 2026-11-08
**Author:** Jovan

## Context

The conventions in `docs/dev/process/` and `CONTRIBUTING.md` (PR title format, fixed scope list, branch names, `Closes JOB-x` lines, one layer per PR) are only enforced by memory and by the `pr-reviewer` agent, and they drift. Humans and agents both need fast, automatic feedback on the PR itself.

Promoted from JOB-292 (Future Consideration, PRJ-002) into PRJ-013 / MIL-040. This ADR is JOB-295.

### Facts from the existing system that shape this design

- **Squash-merge only**, with `squash_merge_commit_title = PR_TITLE` and `squash_merge_commit_message = PR_BODY`. The commit on `main` is exactly the PR title plus the PR body. Branch commits never reach `main`.
- **`main` has no branch protection.** A failing check today is a red ✗, not a blocked merge.
- **Drift in the last 80 merged PRs (#419–#500):** bare scopes `chore:` (#456, #457, #475) and `test:` (#464); scope `e2e` used but not in the list (#420, #425, #426), while other Cypress-only PRs used `(frontend)`; no JOB ID at all (#420, #462); more than one of db/backend/frontend in one PR (#431, a migration plus its backend integration test). #483 touched the migration and regenerated jOOQ classes only, which is one layer (see below).
- **The scope drift JOB-292 cited is already fixed:** `adr` is in WORKFLOW.md's fixed list. `e2e` is not, although E2E has its own job type (`E2E:`) and branch prefix (`e2e/`).
- **The PR template** (`.github/PULL_REQUEST_TEMPLATE.md`) already has the `Closes JOB-x` section (JOB-313, ADR-0055), but its "Type of change" checklist duplicates the title, and its "PR title format" examples (`feat(user)`, `fix(auth)`, `docs(readme)`) break the fixed scope list.
- **`scripts/opsclear`** (stdlib-only Python, unit tests in `scripts/opsclear_test.py`, run by CI on `scripts/**` changes) already has `pr sync` with event-file reading, `JOB_REF_RE`, `CLOSES_LINE_RE` and `parse_pr_refs` (HTML comments stripped).
- **`job-sync.yml`** (ADR-0055) runs `main`'s copy of `scripts/` on PR events, reading PR text from the event file and never from the shell. ADR-0055 left validating branch names and commit formats to this milestone.
- **`ci.yml` is path-filtered** (`backend/**`, `frontend/**`, `scripts/**`, `ci.yml`), so its jobs don't run on docs-only PRs and can't be required checks.
- **jOOQ classes** generated by a DB job live in `backend/src/main/generated/`, so a DB-migration PR touches backend paths by design.
- **`pr-reviewer`** (ADR-0054, JOB-307) already checks title, branch, body and one-layer by hand, and posts one review comment.
- **Naming rules are spread out:** job titles in JOBS.md, branches and commits in WORKFLOW.md, PR title and body in CONTRIBUTING.md, plus a copy of the scope list in CLAUDE.md.
- There are no bot PR authors (no Dependabot or Renovate). Every PR so far is from the maintainer or their agents.

## Decision

Add a `scripts/opsclear pr check` command and a `.github/workflows/pr-checks.yml` workflow that runs it on every PR to `main`. It checks the PR title, branch name, PR body and layer separation, and **fails on any violation**. A `cross-layer` label is the only escape hatch, and only for the layer check. The check becomes a **required status check** on `main` that admins can bypass. Add `e2e` to the fixed scope list. Collect all naming rules in a new `docs/dev/process/NAMING.md` that the check is tested against. `pr-reviewer` keeps its own checks unchanged. No DB, backend or frontend changes.

## Product decisions

### What is checked

| Check | Rule | Fails when |
|---|---|---|
| **PR title** | `<type>(<scope>): <summary> (JOB-x)`. Type from `feat fix docs refactor test chore`, scope from the fixed list, non-empty summary, one or more job IDs at the end (`(JOB-1)` or `(JOB-1, JOB-2)`) | Wrong shape, unknown type or scope, missing scope, missing job ID |
| **Branch name** | `<feature\|fix\|e2e\|chore>/JOB-x-<slug>`, slug lowercase `a-z0-9-` | Wrong prefix or shape, or its job ID isn't one of the title's |
| **PR body** | A `Closes JOB-x` or `Part of JOB-x` line naming a job from the title. No unfilled `JOB-___` placeholder. No AI attribution | Line missing or names other jobs only; placeholder left; a `Co-Authored-By` line for an AI tool (Claude, Anthropic, Copilot, OpenAI, ChatGPT, Gemini, Cursor) or a "Generated with Claude Code" line |
| **Layers** | At most one of db / backend / frontend (see below) | Two or more layers touched and no `cross-layer` label |

Text inside `<!-- -->` is ignored for the body checks, as in ADR-0055. The title and body are checked because they become the commit on `main`. Individual branch commits are not checked.

### Fixed scope list

`e2e` is added. The list becomes:

`backend` `frontend` `db` `e2e` `auth` `config` `ci` `docs` `deps` `infra` `adr`

Cypress-only PRs use `test(e2e)` (or `fix(e2e)` for a flaky-test fix). A job ID is **always required**: work without a job gets a Maintenance job first (WORKFLOW.md, one job = one PR).

### What counts as a layer

| Layer | Paths |
|---|---|
| db | `backend/src/main/resources/db/migration/**`, `backend/src/main/generated/**` |
| backend | everything else under `backend/` |
| frontend | everything under `frontend/` except `frontend/cypress/**` |
| neutral | `frontend/cypress/**`, `docs/**`, `.github/**`, `.claude/**`, `scripts/**`, `api/**`, `keycloak/**`, root files |

Neutral paths can join any one layer: a frontend job with its E2E specs, a backend bug fix with a Cypress regression test (#496), a backend PR that updates the Postman collection. The check fails only when **two or more of db / backend / frontend** are touched.

### Strictness and escape hatch

- **Every check fails** the workflow. There are no warnings.
- **`cross-layer` label**: adding it to the PR re-runs the check and passes the layer check. The run summary still lists the layers touched. It doesn't affect the title, branch or body checks.
- **Required check, admin bypass**: branch protection on `main` requires the `Process check` status. `enforce_admins` stays off, so the maintainer can override in an emergency (e.g. a GitHub "Revert" PR, whose branch name can't be changed).

### Relationship to `pr-reviewer`

Both check everything: `pr-reviewer` keeps its process checklist unchanged. CI gives an immediate, mechanical pass/fail. The reviewer still judges whether a `cross-layer` label is justified, whether the scope matches the job, tests and code.

### Naming rules in one place

A new `docs/dev/process/NAMING.md` becomes the single source for every naming rule:
- job titles (moved from JOBS.md)
- branch names (from WORKFLOW.md)
- commit subjects, PR titles, types and the fixed scope list (from WORKFLOW.md and CONTRIBUTING.md)
- PR body lines (`Closes` / `Part of`) and the AI-attribution rule
- the `cross-layer` label, and which paths make up each layer
- ADR and Flyway migration file names (pointing to their existing docs)

WORKFLOW.md, JOBS.md, CONTRIBUTING.md and CLAUDE.md keep a one-line summary and link to NAMING.md, instead of their own copies of the lists.

### Process-docs audit

The process docs repeat rules and already drift (the PR template's example titles). JOB-323 audits every Markdown file that describes the process (process docs, CONTRIBUTING, CLAUDE.md, templates, skills, agents) against the code and these checks, and fixes them. It was created alongside this ADR and runs after the docs are wired up (see Implementation order).

## Technical design

### Database

None.

### API

None.

### `scripts/opsclear pr check`

```
scripts/opsclear pr check --event "$GITHUB_EVENT_PATH" --summary "$GITHUB_STEP_SUMMARY"
scripts/opsclear pr check --title '…' --body-file pr.md [--branch …] [--labels a,b] [--base origin/main]
```

- **CI mode** (`--event`): reads title, body, head branch, labels and PR number from the event file. Reads the changed files from `GET /repos/{repo}/pulls/{n}/files` (paginated, `GITHUB_TOKEN`, stdlib `urllib`).
- **Local mode**: branch defaults to the current git branch, files to `git diff --name-only <base>...HEAD`. Agents and `/ship` run it before `gh pr create`. It needs no API key.
- **Runs every check and reports all failures**, not just the first. Each failure prints a GitHub `::error title=…::` annotation with how to fix it, and the run summary gets a table (check / pass or fail / detail). Exit 1 if any check fails, otherwise 0.
- **Reuses** `JOB_REF_RE`, `CLOSES_LINE_RE` and the HTML-comment stripping from `pr sync`.
- **Rule constants** (`TYPES`, `SCOPES`, `BRANCH_PREFIXES`, `LAYER_PATHS`, `AI_ATTRIBUTION_RE`) live in the script.
- **Doc-sync test**: a unit test parses NAMING.md's types and scope lines and branch prefix table, and fails if they differ from the constants. Changing a scope means one PR touching both.
- **Unit tests** (no network): every title, branch and body rule with good and bad examples taken from the real PRs listed under Context, layer classification for each path group, `cross-layer` label, multiple jobs, HTML comments, local-mode git fallbacks.

### `.github/workflows/pr-checks.yml`

```yaml
name: PR checks
on:
  pull_request:
    branches: [main]
    types: [opened, edited, synchronize, reopened, labeled, unlabeled]
permissions:
  contents: read
  pull-requests: read
concurrency:
  group: pr-checks-${{ github.event.pull_request.number }}
  cancel-in-progress: true
jobs:
  process-check:
    name: Process check
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v7
        with:
          ref: main
          sparse-checkout: scripts
          persist-credentials: false
      - uses: actions/setup-python@v7
        with:
          python-version: '3.12'
      - name: Check PR against the dev process
        env:
          GITHUB_TOKEN: ${{ github.token }}
        run: python scripts/opsclear pr check --event "$GITHUB_EVENT_PATH" --summary "$GITHUB_STEP_SUMMARY"
```

- **`main`'s copy of `scripts/`**, as in job-sync: a PR can't loosen the rules it's checked against.
- **No path filter**, so the check always reports and can be required (unlike `ci.yml`'s jobs).
- **`edited`, `labeled`, `unlabeled`** re-run it when the title or body is fixed or the `cross-layer` label changes. `synchronize` re-runs it when new commits change the files.
- **No PR text in the shell**: everything is read from the event file (no script injection).
- **No secrets**, so fork PRs work too.
- The job name `Process check` is the required status name, so it must stay stable.

### Repository settings (manual, maintainer)

- Create the `cross-layer` label (`gh label create cross-layer`, done in the workflow job).
- After the workflow has run once: branch protection on `main` requiring the `Process check` status, `enforce_admins` off, no "require up to date". The maintainer does this by hand. Agents don't change repo settings (AGENTS.md permissions).

### Process docs and tooling

- **NAMING.md** (new) as described under Product decisions. WORKFLOW.md, JOBS.md, CONTRIBUTING.md and CLAUDE.md link to it.
- **WORKFLOW.md**: a "Process checks" section: what's checked, the `cross-layer` label, required-check and admin-bypass rules.
- **PR template**: drop the "Type of change" checklist and the stale "PR title format" examples. Match the CONTRIBUTING.md body (Summary, `Closes JOB-x`, References with job and ADR, Test plan), and link NAMING.md for the title.
- **`/ship` and the implementation agents**: run `scripts/opsclear pr check` locally before `gh pr create` and fix what it reports.
- **AGENTS.md / DEV-GUIDE.md**: the check, local mode and the `cross-layer` label.
- **`pr-reviewer`**: unchanged.

### Constraints & edge cases

- **Rule changes lag one PR**: the PR that changes the rules (e.g. adds a scope) is checked by `main`'s old rules. Don't use the new rule in that same PR, or use the admin bypass.
- **Open PRs when the check goes live** fail until their title or body is edited. Editing re-runs the check, since `edited` is a trigger.
- **GitHub "Revert" PRs** (`Revert "…"`, branch `revert-N-…`) fail. Retitle the PR and use the admin bypass, or recreate it from a properly named branch.
- **Several jobs in one PR**: the title lists them all. The branch job and at least one `Closes` / `Part of` job must be among them.
- **A `JOB-x` in `Closes` but not in the title** passes if another line names a title job (it matches job-sync's union of references).
- **Over 3000 changed files**: the files API truncates. The check fails with a message to split the PR.
- **GitHub API errors** while listing files: retried briefly, then the check fails with the error. A required check must not pass silently on missing data.
- **A DB bug fix with its integration test** (like #431: a migration plus a test under `backend/src/test`) touches db and backend, so it needs the `cross-layer` label.
- **Draft PRs** are checked too, so problems show up early.

## Alternatives considered

### Format checks fail, layer check only warns
Rejected (decided). Warnings are easy to ignore. With a `cross-layer` label, legitimate exceptions stay cheap and visible.

### Everything warns
Rejected (decided). Same reason, and a warning can't be a required check.

### Exempt `chore` / `refactor` from the layer check by type
Rejected (decided). An explicit label shows the intent on each PR. A type exemption would let any chore cross layers silently.

### E2E as its own layer
Rejected (decided). Frontend jobs and bug fixes legitimately ship Cypress specs. Making them use the label every time would make it meaningless.

### `no-job` label to skip the job ID
Rejected (decided). Every PR has a job (one job = one PR). Revisit if a bot starts opening PRs.

### CI owns the mechanical checks and `pr-reviewer` drops them
Rejected (decided). Keep both. The reviewer's checklist is cheap and also covers PRs reviewed before this lands.

### Layer separation only in `pr-reviewer`
Rejected (decided). The reviewer runs only through `/implement`. CI covers every PR.

### Not required / required without admin bypass
Rejected (decided). Not required makes a red ✗ advisory. No bypass leaves Revert PRs and rule-change PRs stuck.

### Third-party action (`amannn/action-semantic-pull-request`) plus a script
Rejected (decided). Two places to configure types and scopes, and it can't check branch, body or layers. `scripts/opsclear` already has the parsing and tests.

### Separate `scripts/pr_check.py`
Rejected (decided). It would duplicate `pr sync`'s event reading and reference parsing.

### Run the PR's own copy of the check
Rejected (decided). A PR could weaken its own check. The cost is that rule changes take effect one PR later.

### Parse NAMING.md at runtime
Rejected (decided). The check would break on a wording change. Constants plus a doc-sync test fail loudly in the PR that causes the drift.

### Sticky PR comment
Rejected (decided). Annotations and the run summary are enough. A comment updated on every edit is noise next to `pr-reviewer`'s comment.

### Lint every branch commit (commitlint)
Rejected. With squash merges, branch commits never reach `main`. Only the title and body do.

## Consequences

### Positive
- Every PR gets immediate, automatic feedback on title, branch, body and layers, and a required check stops bad merges.
- `main`'s history stays consistent, because the squash commit is exactly what's checked.
- Agents can run the same check locally before opening a PR.
- One file (NAMING.md) holds every naming rule, and a test keeps the check aligned with it.

### Negative
- More friction: a typo in a title blocks the merge until it's edited.
- Format rules are checked twice, by CI and by `pr-reviewer`.
- Rule changes take effect one PR later, and Revert PRs need the admin bypass.
- Branch protection is a manual repo setting outside version control.

### Neutral
- `e2e` joins the fixed scope list.
- New `cross-layer` label and a new required status, `Process check`.
- The PR template, WORKFLOW.md, JOBS.md, CONTRIBUTING.md, CLAUDE.md, AGENTS.md, DEV-GUIDE.md, `/ship` and the implementation agents change, and JOB-323 audits all process docs afterwards.

## Implementation order

All jobs are `Chore:` jobs (no DB, backend or frontend layer).

1. **Chore 1: `scripts/opsclear pr check` and NAMING.md**: the command (CI and local modes, all four checks, annotations, run summary, exit codes), unit tests, and NAMING.md with all naming rules including the `e2e` scope. The doc-sync test needs NAMING.md, so it ships here. WORKFLOW.md and JOBS.md replace their lists with links to it. *Not blocked.*
2. **Chore 2: `pr-checks.yml` workflow**: the workflow as above and the `cross-layer` label, verified on a test PR (bad title, bad branch, missing `Closes`, cross-layer with and without the label). Then the maintainer makes `Process check` a required status on `main`. *Blocked by Chore 1.*
3. **Chore 3: wire the checks into the dev process**: PR template rewrite, WORKFLOW.md "Process checks" section, CONTRIBUTING.md and CLAUDE.md link to NAMING.md, AGENTS.md and DEV-GUIDE.md document the check and the label, `/ship` and the implementation agents run `pr check` before `gh pr create`. *Blocked by Chore 2.*
4. **JOB-323: audit and fix all dev-process Markdown docs** (already created): every process doc, template, skill and agent checked against the code and these rules; contradictions and duplicate rules fixed. *Blocked by Chore 3.*
